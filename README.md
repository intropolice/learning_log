# Learning Log — учебный журнал

**Готовый локальный демо-профиль:** логин `demo`, пароль `LearningLog2026!`. Он автоматически создаётся при запуске через `start.py` / `start.sh`; включает 3 темы и 6 записей. Подробнее: [DEMO.md](DEMO.md). Это публичный учебный аккаунт, не для личных данных или публикации.

**Обновление запуска:** если в браузере `ERR_CONNECTION_REFUSED`, начните с [START-HERE.md](START-HERE.md). Добавлен запуск `sh start.sh` (Linux/macOS) или `py -3.12 start.py` (Windows). Сервер должен оставаться запущенным в терминале.

Готовый Django-проект по [учебному ТЗ](https://xn--80aaxhb0ahs.xn--h1adrf.xn--p1ai/proekt-learning_log.html).

**Статус:** исходники и миграции подготовлены, локальные автоматические и браузерные проверки выполнены. Проект не опубликован на GitHub и не развёрнут на учебном сервере. Для окончательной сдачи по ТЗ нужны **две ссылки**: публичный репозиторий и работающий сайт на IP учебного сервера с выделенным портом. Архив сам по себе не заменяет эти ссылки.

## Возможности

- Регистрация, вход, выход POST-запросом с CSRF-защитой.
- Личный список тем; создание темы (не более 200 символов).
- Добавление и редактирование текстовых записей внутри темы.
- Дата создания сохраняется автоматически; темы — от старых к новым, записи — от новых к старым.
- Доступ к чужой теме, добавлению или изменению чужой записи возвращает 404.
- Гости перенаправляются на страницу входа; после входа открывается запрошенная страница.
- Административная панель `/admin/` с моделями Topic и Entry.
- Русский адаптивный интерфейс на Bootstrap 4 / django-bootstrap4. Bootstrap и jQuery включены локально: внешние CDN при просмотре не нужны.
- SQLite, Gunicorn, WhiteNoise, Docker Compose, постоянный том для базы.
- 39 автоматических тестов: права доступа, валидация, создание/редактирование, регистрация, вход/выход, CSRF, экранирование HTML и порядок записей.

## 1. Локальный запуск (Python 3.12)

Распакуйте папку `learning_log` в `Документы/<ваша-фамилия-латиницей>/` (Windows/macOS: `Documents`). Откройте в VS Code **папку с `manage.py`**, не вложенный пакет настроек.

**Linux / macOS** — из папки с `manage.py`:

```sh
python3.12 -m venv ll_env
source ll_env/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

**Windows PowerShell:**

```powershell
py -3.12 -m venv ll_env
.\ll_env\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

Если PowerShell запрещает активацию, можно без неё выполнить команды через `.\ll_env\Scripts\python.exe` вместо `python`.

Откройте http://127.0.0.1:8000/. Создайте аккаунт через «Регистрация», добавьте тему и запись. Для готового демо выполните `python manage.py seed_demo` перед `runserver` или используйте `sh start.sh` / `py -3.12 start.py`: логин `demo`, пароль `LearningLog2026!`. База и реальные личные данные в архив не включены. Остановить сервер: Ctrl+C. При следующем запуске достаточно активировать существующее окружение и вызвать `runserver`.

Для административной панели создайте собственного суперпользователя:

```sh
python manage.py createsuperuser
```

Затем откройте http://127.0.0.1:8000/admin/. Администратор по назначению Django имеет доступ к данным всех пользователей, обычные пользователи — только к своим.

Проверки (сервер запускать не нужно):

```sh
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test --verbosity 2
```

Ожидается `Ran 39 tests` и `OK`. Тесты используют отдельную временную БД. Создавать новые миграции при первом запуске не требуется: они уже включены. `ll_env` создаётся на вашем компьютере и не входит в архив или Git.

## 2. Docker Compose

Требуются Docker Engine с Compose v2 или Docker Desktop (Linux containers).

Из папки с `compose.yaml`:

```sh
cp .env.example .env
```

В PowerShell: `Copy-Item .env.example .env`.

Создайте случайный ключ командой Python (или в активированном окружении):

```sh
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Вставьте результат в `DJANGO_SECRET_KEY` файла `.env`. Примерный ключ из `.env.example` **обязательно замените**. В production без отдельного ключа приложение не запускается; требуемая длина — от 50 символов. Настройте переменные по таблице ниже, затем:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 web
```

Локальный пример открывается по http://127.0.0.1:8000/. Миграции и сборка статики выполняются автоматически перед запуском Gunicorn. Проверка доступности выполняется healthcheck. По инструкции учебного сервера использован один worker Gunicorn с четырьмя потоками.

```sh
# Создать администратора (интерактивно)
docker compose exec web python manage.py createsuperuser
# Запустить тесты
docker compose exec web python manage.py test
# Остановить с сохранением базы
docker compose down
# Применить изменения кода
docker compose up -d --build
```

SQLite находится в именованном томе `learning_log_data`, смонтированном в `/app/data`. База переживает пересоздание контейнера и обычный `docker compose down`. **Не добавляйте `-v` к `down`: это удалит том и данные.** Для резервной копии используйте SQLite backup или остановите сервис перед копированием файла, не копируйте занятую базу произвольным образом.

### Переменные окружения

Django читает переменные окружения. Compose загружает `.env` автоматически. При обычном локальном запуске `manage.py` файл `.env` сам по себе **не загружается**: действуют безопасные для локальной разработки значения по умолчанию; для особых настроек экспортируйте переменные в терминале.

| Переменная | Назначение | Пример / значение для локального Docker |
|---|---|---|
| `DJANGO_SECRET_KEY` | Секрет подписи сеансов; индивидуальный, случайный, от 50 символов | Сгенерируйте самостоятельно |
| `DJANGO_DEBUG` | Режим отладки | `False` на сервере; при обычном локальном запуске по умолчанию `True` |
| `DJANGO_ALLOWED_HOSTS` | Разрешённые имена и IP через запятую, без схемы и порта | `localhost,127.0.0.1`; на сервере добавьте его IP |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Доверенные origin со схемой и портом | `http://127.0.0.1:8000`; на сервере `http://<IP>:<ПОРТ>` |
| `DJANGO_USE_HTTPS` | HTTPS-redirect и защищённые cookies | `False` для доступа по HTTP/IP; `True` только при настроенном HTTPS |
| `SQLITE_PATH` | Путь к базе в контейнере | `/app/data/db.sqlite3` |
| `APP_BIND_IP` | Интерфейс хоста для публикации порта | `127.0.0.1` локально, `0.0.0.0` на учебном сервере |
| `APP_PORT` | Свободный внешний порт проекта | `8000` локально, первый выделенный порт на сервере |

Не используйте `ALLOWED_HOSTS=*`. Секрет и `.env` нельзя публиковать или пересылать вместе с исходниками. Для HTTPS потребуется доверенный reverse proxy, перезаписывающий `X-Forwarded-Proto`; не доверяйте этому заголовку от произвольных внешних клиентов.

## 3. Учебный сервер и GitHub — оставшиеся шаги сдачи

Следуйте [разделу «Деплой на сервер»](https://xn--80aaxhb0ahs.xn--h1adrf.xn--p1ai/deploi-na-server.html). Не используйте чужие каталоги или порты.

1. Получите доступ к GitHub и учебному серверу у преподавателя. Сеть учебного сервера должна быть доступна с вашего компьютера (при необходимости через предоставленный учебный VPN).
2. В терминале сервера выполните `newproject <ваша-фамилия>-learning-log`. Запишите выданный каталог и **первый порт** диапазона. Фамилия и фактический порт не подставлены: они не были предоставлены.
3. Создайте пустой **публичный** репозиторий GitHub. На своём компьютере, из папки с `manage.py`, выполните, подставив свои данные:

```sh
git init
git config user.name "ВАШЕ ИМЯ"
git config user.email "ВАША ПОЧТА"
git add .
git status
# Убедитесь, что .env, база и ll_env отсутствуют в подготовленных файлах.
git commit -m "Learning Log"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/learning_log.git
git push -u origin main
```

Авторизуйтесь штатным способом GitHub (токен/менеджер учётных данных). Не помещайте токен в URL, код или README.

4. Загрузите содержимое репозитория в **каталог, выданный `newproject`**, сохранив созданный сервером `.env`. Например, скачайте публичный репозиторий во временный каталог, затем перенесите его содержимое в каталог проекта; не выполняйте `git clone ... .` в непустом каталоге с `.env`.
5. Настройте серверный `.env`: фактический IP в `DJANGO_ALLOWED_HOSTS`; `http://<IP>:<ПОРТ>` в `DJANGO_CSRF_TRUSTED_ORIGINS`; `APP_BIND_IP=0.0.0.0`; выданный `APP_PORT`; `DJANGO_DEBUG=False`; индивидуальный секрет; `SQLITE_PATH=/app/data/db.sqlite3`; `DJANGO_USE_HTTPS=False` для HTTP.
6. Из каталога проекта запустите `docker compose up -d --build`. Проверьте `docker compose ps`, логи и `http://<IP>:<ПОРТ>/` из браузера в учебной сети.
7. Создайте аккаунты и пробные темы заново: локальная база в архив не включена и автоматически на сервер не переносится.
8. Сдайте ссылку на публичный GitHub и проверенную ссылку на приложение. Внешний домен и HTTPS по ТЗ не обязательны, преподаватель подключает их по запросу.

**Сейчас эти два публичных результата не созданы.** Также здесь не выполнялись реальная сборка Docker-образа и запуск контейнера: локальные проверки приложения описаны в `docs/verification.md`.

## Структура

```text
manage.py
learning_log/         # настройки, корневые URL, WSGI/ASGI
learning_logs/        # модели, формы, представления, миграция, тесты, шаблоны
users/               # регистрация, маршруты входа/выхода, тесты, шаблоны
static/              # стили и локальные Bootstrap/jQuery
static/vendor/       # сторонние библиотеки, лицензии и карты исходников
templates/           # страницы 403, 404, 500
docs/                # результаты проверки и снимки интерфейса
Dockerfile
compose.yaml
requirements.txt     # зафиксированные версии runtime-зависимостей
.env.example         # образец, не рабочий секрет
```

Итоговое состояние моделей создано одной начальной миграцией, а не цепочкой промежуточных миграций учебника. Это позволяет разворачивать чистую БД сразу с владельцами тем и не назначать существующим данным фиктивного владельца.

Самостоятельные работы «Система управления задачами» и «Блог» внизу страницы — отдельные задания; в этот проект Learning Log они не включены. Отправка почты, восстановление пароля и удаление через пользовательский интерфейс в данном ТЗ не требуются и не реализованы.

## Если что-то не запускается

- `400 Bad Request`: добавьте фактический IP/домен в `DJANGO_ALLOWED_HOSTS`, перезапустите Compose.
- Ошибка CSRF: проверьте схему, IP и порт в `DJANGO_CSRF_TRUSTED_ORIGINS`.
- Нет входа по HTTP: установите `DJANGO_USE_HTTPS=False`.
- `port is already allocated`: используйте свой выделенный порт, проверьте `newproject`.
- `no such table`: выполните миграции и проверьте путь `SQLITE_PATH`.
- Ошибка ключа: замените `DJANGO_SECRET_KEY` на новый случайный ключ длиной от 50 символов.
- Нет изменений после правки кода: пересоберите через `docker compose up -d --build`.
- Нет оформления в production: проверьте результат `collectstatic` и логи WhiteNoise.
